小米账号与设备

第一次配置，按这四个步骤走：
  1. 填上面的小米账号和密码，点「保存」。（建议用小号，同账号会顶掉手机小爱）
  2. 点「发现设备」——它会从小米云端把你这账号下的音箱连同 DID 和型号一起列出来，不需要你手抄。
  3. 表格里每行左侧勾上「接管」，保存。只有一台时可以直接点那一行，DID 和型号会自动填好。
  4. 确认是接真机后，取消勾选「演示模式」，回顶部点「启动桥接」。

找不到设备？先在米家 App 里确认这台音箱确实挂在这个账号下、且已通电联网；账号密码错误会在这一步报出来。

这一页决定「从哪台音箱取语音、往哪台音箱播报」。填完记得点保存，再回顶部启动桥接。

首次登录可能被要求验证码。小米会在新设备或新 IP 上下发短信/邮箱验证码，弹出的输入框填一次即可；通过后 token 缓存在 data/.mi.token，之后不再重复索要。删掉这个文件就要重新验证。

唤醒词与播报

小爱仍会先自己回答一遍，工作台是抢在它之后覆盖播报。所以唤醒词要足够特别，避免日常聊天被误接管。

语音只播摘要，长内容留在会话记录里。
播报链路：模型回答 → 去掉 Markdown 与代码块（压成「代码略」）→ 按句子边界截到上限 → 注入音箱。 所以回答里的细节不会念出来，想听完整内容就放长字数上限，或者到「会话记录」看原文。

自定义场景

          
把一串设备操作打包成一个词，说「小助手，执行睡觉」就能一次做完。保存后立即可用，不需要重启。

          

            
            
          

          
          

            
            
          

          

            步骤只有三种形式：
            
    
              
  • {"device":"客厅灯","prop":"power","value":"开"} — 写属性，开关类用 开/关，数值类直接给数字
    • 
              
  • {"device":"书桌插座","action":"toggle"} — 执行动作，需要先查该设备的能力
    • 
              
  • {"delay":0.5} — 等 0.5 秒，设备之间需要缓冲时用
    • 
            

            单步失败不会中断整个场景，最后一起汇报成功和失败。保存前会校验结构，写错了当场提示。
